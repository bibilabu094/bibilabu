# 接口与模型说明

本页说明两种客户端为什么要填写不同的 Base URL。示例域名使用 `https://gate.bibilabu.cc`，它是作者当前使用的平台演示地址；使用其他平台时应整体替换为自己的 API 地址。

## 已验证的接口用途

| 接口 | 用途 | 对应客户端 |
| --- | --- | --- |
| `/v1/models` | 返回当前账号可用的模型列表 | 按平台约定使用的辅助检查 |
| `/v1/messages` | Anthropic Messages 兼容请求 | Claude Code |
| `/v1/responses` | OpenAI Responses 兼容请求 | Codex，使用 GPT 系列模型 |
| `/v1/chat/completions` | OpenAI Chat Completions 兼容请求 | ChatBox、Cherry Studio、Cline、Roo Code、LangChain 和代码调用 |

可用模型、权限和余额以你的 API 平台控制台为准。若平台实现了 `/v1/models`，它可用于辅助查看模型；但 Claude Code 是否能对话应以 `/v1/messages` 最小请求或客户端实际消息为准。

## 为什么 Claude Code 不带 `/v1`

Claude Code 需要的是服务根地址。它会自行拼接 Anthropic Messages 路径，所以配置文件中应是：

```text
https://gate.bibilabu.cc
```

若填成 `https://gate.bibilabu.cc/v1`，客户端会得到错误路径，因此不要额外添加 `/v1`。

## 为什么 Codex 必须带 `/v1`

Codex 的 `responses` 协议会以配置的 `base_url` 为基础请求 Responses 接口，所以 `config.toml` 中应写：

```text
https://gate.bibilabu.cc/v1
```

并配合：

```toml
wire_api = "responses"
env_key = "BIBILABU_API_KEY"
requires_openai_auth = false
```

## 模型选择规则

- 使用 Claude Code 时，先用 `/status` 和实际消息确认连接；平台支持模型发现时，再在 `/model` 菜单中选择模型。
- 使用 Codex 时，只选择 GPT 系列模型。
- 不要把某个教程、截图或别人电脑上的模型名当作自己的固定清单。
- 若模型未出现，先检查 Key 权限和平台账户状态，再重新启动客户端刷新模型列表。

## 其他客户端怎么选地址

| 客户端或用法 | 协议 | 示例地址 |
| --- | --- | --- |
| ChatBox、Cherry Studio、LangChain | OpenAI | `https://gate.bibilabu.cc/v1` |
| Cline、Roo Code | OpenAI 或 Anthropic | OpenAI 选带 `/v1`；Anthropic 选不带 `/v1` |
| Claude Code | Anthropic | `https://gate.bibilabu.cc` |
| Codex | OpenAI Responses | `https://gate.bibilabu.cc/v1` |

完整的 Python、curl 和 Anthropic 请求格式见 [OpenAI / Anthropic 兼容接入](06-OpenAI与Anthropic兼容接入.md)。
