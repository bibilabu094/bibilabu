# 常见问题

## 1. `401`、认证失败或 Key 无效

按下面顺序检查：

1. 确认 `YOUR_API_KEY` 已替换为你自己的有效 Key，而不是保留了示例文字。
2. 确认 Key 没有复制到额外空格、引号或换行。
3. 在 API 平台控制台确认 Key 未被删除、禁用或过期。
4. 完全退出客户端后重新启动。Claude Code 执行 `claude`，Codex 执行 `codex`。

不要把完整 Key 发给客服。排查时只说明错误码、客户端类型和你使用的配置文件路径即可。

## 1.1 `npm` 或 `claude` / `codex` 命令不存在

先按 [Node.js 与 npm 前置环境](00-Node.js与npm前置环境.md) 运行 `node -v` 和 `npm -v`。两条命令都要能显示版本号。

若 `npm install -g ...` 已执行成功但 `claude --version` 或 `codex --version` 仍不存在，关闭当前终端并重新打开，再执行版本检查。Windows 上若提示 `npm.ps1` 被禁止执行，按前置环境页面中的 PowerShell 步骤处理。

## 2. 404 或路径不存在

最常见原因是 Base URL 的 `/v1` 写反了：

- Claude Code 的 `ANTHROPIC_BASE_URL` 不带 `/v1`。
- Codex 的 `base_url` 必须带 `/v1`。

改完后保存文件并重启对应客户端。

## 3. Codex 报 `unknown variant openai`

打开 `%USERPROFILE%\\.codex\\config.toml`（macOS/Linux 为 `~/.codex/config.toml`），找到 `wire_api`。它必须是：

```toml
wire_api = "responses"
```

不要写 `openai` 或 `chat`。

## 4. Codex 看不到模型，或 Claude 模型无法工作

Codex 使用 `/v1/responses`，当前已验证该路径用于 GPT 系列模型。Claude 模型应使用 [Claude Code 配置](02-Claude-Code-配置.md)。

对于 GPT 模型，确认 `config.toml` 中有：

```toml
discover_models = true
```

保存后重启 Codex，输入 `/model` 重新读取列表。

## 5. 明明修改了文件，客户端仍使用旧配置

检查是否编辑了正确的文件：

| 客户端 | Windows 文件 | macOS/Linux 文件 |
| --- | --- | --- |
| Claude Code | `%USERPROFILE%\\.claude\\settings.json` | `~/.claude/settings.json` |
| Codex 密钥 | `%USERPROFILE%\\.codex\\auth.json` | `~/.codex/auth.json` |
| Codex 主配置 | `%USERPROFILE%\\.codex\\config.toml` | `~/.codex/config.toml` |

保存后关闭所有该客户端窗口，再从新终端重新启动。

## 5.1 Codex 的 `auth.json` 被保存成了文本文件

Windows 默认可能隐藏扩展名，导致你看到的是 `auth.json`，实际文件却是 `auth.json.txt`。打开文件资源管理器的“查看”，启用“文件扩展名”，确认文件的完整名称就是 `auth.json`。

## 6. 我想把教程示例换成自己的平台

全文搜索 `gate.bibilabu.cc`，替换为你的平台域名。替换后再次检查：

- Claude Code 地址末尾没有 `/v1`。
- Codex 地址末尾有 `/v1`。
- Key 使用你自己的平台新建的 Key。
- 模型通过 `/model` 从你自己的平台列表中选择。
